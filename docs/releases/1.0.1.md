# System 1.0.1

> Release snapshot for 1.0.1. Subsequent [public-workload evidence](../../benchmarks/quality/workloads/README.md) adds live Jev/Gemini observations without changing the runtime. The statement about no new teacher calls below refers to the release work, not that later evaluation.

This patch improves the supplied teaching examples and first-use game policies,
and adds an externally labeled banking-support demonstration. The product remains
the same small loop: teach one bounded skill, validate it, save it, and reuse it
locally. There are no new runtime dependencies or public API changes. Existing
saved skills retain their behavior; rerun an example to get its updated lessons
and calibration.

## Routing confidence

The routing example adds 60 separate calibration cases covering mechanical text
changes, ordinary explanation, and independent reasoning over similar subject
matter. Its 156 teaching cases and fitted weights are unchanged from the previous
contrast round. Compiler settings, alpha 0.05, and strict review stay unchanged.
Calibration changes uncertainty sets, not the raw class predictions.

| Routing cohort | Correct raw, both versions | Accepted, before → after | Accepted errors, before → after |
|---|---:|---:|---:|
| Original 96 cases, development | 95/96 | 95 → 94 | 1 → 0 |
| Prior 24 diagnostic cases, development | 24/24 | 24 → 24 | 0 → 0 |
| Prior 24 confirmation cases, now development | 22/24 | 23 → 20 | 2 → 1 |
| New 48 confirmation cases | 44/48 | 47 → 44 | 3 → 3 |

Among the 144 previously examined cases, accepted errors fall from three to one;
138 answers are accepted, with 137 correct. The earlier JSON-to-TOML error and
an incorrect proof-verification route now request review. An incorrect route for
summarizing a lemma remains accepted.

**The fresh 48-case cohort misses the 95% accepted-correctness target:** it accepts
44 answers, 41 correct (93.2%), versus 44/47 (93.6%) before calibration. Its three
accepted mistakes concern checking a formal certificate, diagnosing divergent
replicas, and explaining theorem commentary. Calibration also defers three
previously accepted correct answers. This is a bounded improvement on known
distinctions, not evidence that calibration solved general routing confidence.

The first attempt used 36 new calibration examples and did not remove the known
accepted mistakes. Twenty-four shorter cases were then added, retaining all 60.
Only then was the new 48-case cohort authored and evaluated. Its failures remain
in the report; neither its cases nor its results were used to change the final
data or settings. Teaching-file hashes freeze that boundary. All routing cases
are AI-authored and share authorship and policy concepts, limiting independence.

## A real-data support skill

The banking example uses public BANKING77 queries and original labels for three
preselected intents: card arrival, lost or stolen card, and cash withdrawal fees.
It teaches from 287 official training queries and calibrates on 125 separate
training queries. All 120 official test queries for these intents are retained.
The task and existing compiler settings were fixed before test predictions were
examined and were not changed afterward.

| Official banking test slice | Result |
|---|---:|
| Correct raw | 115/120 (95.8%) |
| Accepted locally | 118/120 (98.3%) |
| Correct among accepted | 115/118 (97.5%) |
| Accepted errors | 3 |
| Correctness among accepted, 95% Wilson interval | 92.8–99.1% |

The errors are retained, including ambiguous card-location requests. Two wrong
raw predictions request review. The point targets pass, but the interval does
not establish 95% population precision. This is one bounded support task on a
public dataset, not a full 77-intent benchmark, an out-of-scope detector, a Jev
comparison, or a measurement on live System 1 customer traffic.

Teaching plus calibration took approximately 0.2 seconds, the saved skill was
about 25 KiB, and median uncached inference took about 0.4 ms on the review
machine. Timings exclude data preparation, interpreter startup, imports, receipts,
and downstream application work. [Source, license, and exact split protocol](../../examples/teaching/BANKING77.md).

From an installed repository checkout, teach from JSON, save, and reuse:

```bash
python examples/banking_support.py
system1 decide "My card was stolen" --model .system1/examples/banking_support/skill.s1m --json
```

The first command reads the bundled teaching file, saves the skill, reloads it,
and reports the untouched test slice. The second opens that saved skill in a new
process and returns `intent: lost_or_stolen_card`. Both run locally with no API key.
Applications should honor the returned review flag for uncertain requests.

## Included game and teaching improvements

The earlier [contrast round](../../benchmarks/quality/contrast_round.md) adds six
routing lessons and 28 operation lessons, raising raw correctness on its fresh
72-case confirmation set from 65 to 68. Support lessons remain unchanged.
Operation classifications remain separate from deterministic permissions.

The [game improvements](../../benchmarks/quality/zero_shot/README.md) improve
Pokémon move legality and immediate move ranking, and Paperclips spool pricing
and purchase affordability. Frozen cases improve from 6/24 to 24/24 for Pokémon
and 8/12 to 12/12 for Paperclips. These gains come from explicit game rules; the
raw routing control remains 8/12. They do not establish campaign or speedrun results.

## Reproduce and interpret the checks

```bash
python benchmarks/quality/evaluate_confidence.py
python benchmarks/quality/evaluate_release.py
python benchmarks/quality/evaluate_contrasts.py
python benchmarks/quality/evaluate_zero_shot.py
```

The [confidence report](../../benchmarks/quality/results/confidence_round.json)
retains every prediction, error, review, dataset hash, and confidence interval.
The runner blocks network calls and verifies that saving and reloading preserves
answers, probabilities, prediction sets, and review flags for every case. It also
verifies that routing weights and raw predictions remain unchanged.

The initial all-cohort target check failed on fresh routing. The report continues
to record `all_cohorts_meet_targets: false`. Release regression checks require
at least 80% local acceptance and no increase in accepted errors in each routing
cohort, plus 95% accepted correctness and 80% acceptance on the original routing
and banking workloads. A successful regression check permits the disclosed fresh
routing target miss; it does not certify that every cohort meets the target.

The historical contrast report and recorded 1.0 Jev comparison remain reproducible
from their original snapshots. No new teacher calls or Jev labels were added.
The [current primary-example report](../../benchmarks/quality/results/release_1_0_1.json)
checks current manual teaching separately from that recorded teacher baseline.
The offline confidence/reload checks run in the existing pytest suite and CI.

Local release validation passed 1,089 tests with 14 optional tests skipped,
lockfile consistency, wheel/source builds, strict Twine checks, and a fresh wheel
install outside the checkout. The fresh install verified the version, legacy
imports, proto resources, and a decision from the saved banking skill. The source
distribution includes the banking data, attribution, license, and quality evidence.
