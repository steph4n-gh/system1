# System 1 1.1.0

Version 1.1.0 is a compatible feature release: teach a bounded decision skill,
correct it, compare the candidate with the approved skill, and explicitly adopt
the exact passing artifact. It includes the additions merged since the 1.0.3
security release, including PRs [#3](https://github.com/steph4n-gh/system1/pull/3)
and [#4](https://github.com/steph4n-gh/system1/pull/4).

## Teach, compare, adopt

`from system1 import TeachingSession` and `system1 teach` provide one shared
workflow for text classification with a single `ChoiceField`. Explicit lessons,
calibration examples and recurring assessment cases stay separate. Corrections
replace existing labels for the same normalized input. Assessment builds a
candidate while the approved skill continues serving. Adoption rechecks the
evidence and installs the exact assessed bytes; failed or stale candidates cannot
replace the approved skill.

Reports separate raw accuracy, accepted mistakes, review rates and lost useful
answers, with per-case details. The helper requires ambiguity escalation to stay
enabled. Its default development policy requires at least 80% raw accuracy, 50%
acceptance, zero accepted mistakes and zero useful regressions. These are finite
empirical checks, not production accuracy guarantees. Choose workload thresholds
before inspecting candidate results.

The [document workspace](../../examples/teaching_by_doing/README.md) uses this
same workflow, including own-text lessons, corrections, persistent approved
skills, review and explicit adoption. Its sample documents remain fictional;
the workspace does not move real files. Start with the
[Python/CLI guide](../guides/correcting_skills.md).

## Other additions since 1.0.3

- An optional fitted TF-IDF projector, stored inside the skill, and opt-in
  logistic fitting for choice heads. Ridge remains the compiler default;
  SciPy is required only for the optional logistic teaching path.
- An experimental Inbox Zero adapter and n8n workflows with explicit review,
  failure handling and saved-skill reuse. Their workload qualification limits
  remain documented; integration success does not establish classifier quality.
- Repository demonstrations for Snake comparisons, composed courier skills,
  bounded Pokémon teaching and document filing, with retained traces, controls
  and failures. Emulator/browser extras and applicable user-provided assets
  remain separate from the base package.
- Receipt opt-out handling and calibrated-tail lookup improvements, plus
  consistent documentation and distribution-content checks.

The [changelog](../../CHANGELOG.md#110--2026-09-22) lists the full release scope.
The base dependencies remain NumPy and cryptography. System1 is a local decision
runtime, not an LLM; optional teachers and research encoders are separate.

## Evidence and limits

The [BBC correction experiment](../../benchmarks/quality/document_workflow/README.md)
froze its candidates before scoring 400 separate articles. It inspected 400
feedback labels and added 64 targeted lessons to the original 100 lessons;
200 calibration examples and 200 development checks remained separate.

| Candidate | Raw accuracy | Accepted correctness | Accepted mistakes | Reviews |
|---|---:|---:|---:|---:|
| Initial | 92.25% | 357/373 (95.71%) | 16 | 27 |
| Targeted feedback | 93.25% | 329/337 (97.63%) | 8 | 63 |
| Ordinary extra lessons | 93.00% | 310/314 (98.73%) | 4 | 86 |

The raw-accuracy gain is inconclusive, and fewer accepted errors come with more
review. **All candidates failed the default development adoption gate; none was
adopted.** The archived protocol, source snapshot and outcomes describe the exact
pre-release experiment. Releasing 1.1.0 does not turn it into new evidence.

The full 150-intent CLINC / 77-intent banking n8n task remains unqualified. The
[workload index](../../benchmarks/quality/README.md) retains that result, the
bounded-task successes, conventional baselines and earlier failed experiments.
This release improves the teaching workflow; it does not establish generally
superior classification, general reasoning or autonomous game completion.

## Upgrade and compatibility

```bash
python -m pip install --upgrade 'system1==1.1.0'
```

For optional logistic fitting:

```bash
python -m pip install 'system1[teaching]==1.1.0'
```

Existing compiler/engine APIs and the `reflex` compatibility namespace remain
available. The saved-skill format remains v2 and the runtime continues reading
supported v1/v2 files. **Skills using the new TF-IDF projector require a runtime
with TF-IDF support (1.1.0 or newer); upgrade consumers before distributing those
skills.** This is an added projector capability, not a format-version change.
Existing hashed-projector skills remain supported.

The new session directory is a local, single-writer workspace, not a multi-user
service. Before the first successful adoption, no current skill exists. Keep
application review handling and execution permissions explicit. Existing audit
requirements from [1.0.3](1.0.3.md) continue to apply.

Repository demos and complete research artifacts require a Git checkout; they
are not modules supplied by the wheel. The source distribution includes runnable
examples and the compact document-workflow evidence. Large n8n research artifacts
remain in Git, outside the Python distributions.

## Release validation

Release checks cover the full test suite, documentation links and version labels,
lockfile consistency, wheel/source contents, strict distribution metadata,
an isolated wheel install and the existing offline teaching-quality regression.
CI tests Python 3.11–3.14 on Linux and Python 3.13 on macOS. Optional tests without
their required extras or assets remain explicitly skipped.

The release tag must match package/runtime version 1.1.0 and is pushed only after
CI passes on the exact release commit. The tag-triggered publishing workflow
retests source, validates distributions and publishes through PyPI Trusted
Publishing. The published artifact is then installed and checked separately.
