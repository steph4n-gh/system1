# System 1 1.2.0

Version 1.2.0 extends the teaching workflow through independent qualification,
approved revision history, and explicit recovery. A working skill keeps serving
while its candidate is assessed. Development checks and independent qualification
have separate purposes and policies; neither automatically replaces the skill.

## Qualify, adopt, and recover

`TeachingSession.assess(require_qualification=True)` binds the adoption policy
to the exact candidate. `qualify(...)` scores a separately supplied, labeled
cohort, and `adopt()` rechecks both development and required qualification
evidence before installing the exact assessed bytes. Qualification does not
fit features, calibrate the model, or add lessons.

The qualification defaults require a lower bound of at least 95% correctness
among accepted answers and 80% coverage, with a 95% confidence target across
qualification attempts within the session. The first request fixes that target.
For attempt `k`, each of the two exact one-sided binomial bounds receives an
error budget of `(1 - confidence) / (2 * k * (k + 1))`. This spending rule keeps
the total error budget bounded when later revisions use fresh cohorts, including
after failed or interrupted attempts. It prevents repeatedly retrying independent
95% checks until one happens to pass.

Zero observed errors in a small cohort do not establish sufficient evidence;
no accepted answers produce no accepted-correctness estimate. Each attempt
requires a fixed candidate and fresh, conditionally independent, representative
sampling with correct labels. The software does not establish label truth,
independence, representativeness, or performance under changed traffic. The
session confidence scope does not extend to separate session directories.

The full request, source, thresholds, and cohort are saved before predictions.
An interrupted or failed attempt consumes that cohort: it cannot be replaced,
reused for another candidate, or imported later as teaching data. Normalized
text must remain disjoint from teaching, calibration, recurring evaluation,
and earlier qualification requests. Optional `group` identifiers keep related
documents within one session split; qualification accepts one row per group
and rejects previously used groups. Grouping and normalized text checks do not
detect all related documents or paraphrases.

Approved artifacts and their evidence are retained by SHA-256 revision.
`session.history` lists them; `rollback(revision)` validates the saved artifact,
schema, approval policy, and any required qualification before restoring its
exact bytes. Lessons remain available for the next revision. Rollback invalidates
the active candidate assessment, so another adoption requires reassessment.
Failed candidates never enter approved history.

The CLI exposes the same lifecycle:

```bash
system1 teach .system1/support-session --assess --require-qualification
system1 teach .system1/support-session --qualification fresh-cases.json --source "Reserved independently reviewed requests"
system1 teach .system1/support-session --adopt
system1 teach .system1/support-session --history
system1 teach .system1/support-session --rollback FULL_APPROVED_REVISION_DIGEST
```

Each action requires its preceding checks to succeed. The
[teaching guide](../guides/correcting_skills.md) documents initial lessons and
session creation; the [document workspace](../../examples/teaching_by_doing/README.md)
provides the repository's visual teaching workflow.

## Clearer evidence and review

Candidate and qualification reports include accepted correctness, exact lower
bounds, coverage, class-specific counts and errors, and every evaluated case.
Qualification reports also identify the attempt and session confidence scope.
Recurring development reports use descriptive per-cohort bounds and remain
regression evidence rather than independent qualification or part of the session
confidence guarantee. Existing development defaults remain 80% raw accuracy, 50%
coverage, zero accepted errors, and zero lost useful answers; mandatory
qualification is an explicit additional policy.

`decision_details(text)` returns the approved revision, probabilities, prediction
set, review status, and observable review reasons. Unknown vocabulary and an
ambiguous prediction set are observable conditions, not explanations of every
possible model error. Applications still handle review and execution explicitly.
Predictions do not invent or automatically record labels.

Sessions can select `choice_solver="logistic"` at creation. This exposes the
existing optional compiler solver and persists the choice through reopening;
ridge remains the default. Installing `system1[teaching]` provides SciPy for
logistic fitting. Default ridge teaching, qualification, recovery, and running
saved logistic skills require no SciPy. The base dependencies remain NumPy and
cryptography.

## Research and limits

The [bounded research protocol](../../benchmarks/quality/release_1_2/PROTOCOL.md)
compares lesson selection, the existing solver choices, and a task-specific
contrastive candidate where cached assets permit it. Its exploratory screens
are separate from deployment qualification. The
[complete research report](../../benchmarks/quality/release_1_2/README.md) retains
all misses, costs, source restrictions, and the invalidated development cache
attempt. Confirmation was scored once after committed candidate freezes.

At 400 simulated fitting-plus-calibration labels, three-seed mean correct
automatic yield on untouched Emotion confirmation was 0.99% for random lessons,
0.79% for uncertainty selection, and 0.50% for uncertainty plus diversity.
Frozen MiniLM and its contrastive projection reached 52.15% and 52.85% raw
accuracy, but useful acceptance remained below 1%. None passed the frozen
advancement screens. No selector, new encoder, or contrastive head ships.
Public source annotations and separate evaluation labels are additional costs;
human labeling time was not measured. Raw corpora and encoder weights stay
outside distributions.

The new UCI sentiment trial failed development before and after corrections
(70.5% raw accuracy, 20.0% to 21.5% coverage, seven accepted errors).
The API refused qualification and adoption without consuming a cohort.
Its separately frozen Yelp source-shift diagnostic also failed; it is not a
product qualification. A historical three-intent BANKING77 replay verified
approved-skill preservation during faulty edits, refused adoption, restoration
of original labels, exact adoption, prediction parity after reopening, and
byte-for-byte rollback with lessons retained. It uses recurring historical
checks and does not establish a new quality improvement or fresh qualification.

This release does not establish generally superior classification or a
classification breakthrough. Existing full-scope assistant and banking targets
remain unchanged, with their retained failures in the
[quality index](../../benchmarks/quality/README.md).

## Upgrade and compatibility

```bash
python -m pip install --upgrade 'system1==1.2.0'
```

Existing compiler and engine APIs and the `reflex` compatibility namespace remain
available. The saved-skill format remains v2; supported v1/v2 artifacts continue
to load. TF-IDF skills still require a reader with TF-IDF support (1.1.0 or newer).
These lifecycle additions do not add a new skill projector or binary format.

Version 1.1.0 session files reopen without rewriting their stored state; missing
solver settings retain ridge behavior, and existing current skills keep serving.
Reassess old candidate reports before adoption to obtain the richer 1.2.0 evidence
and policy binding. Use 1.2.0 or newer for session directories using qualification,
groups, solver settings, or revision history. An older helper does not understand
those workflow contracts.

The first 1.2.0 adoption also retains an existing current skill from a 1.1.0
workspace. Its history identifies it as a legacy approved skill when the old
assessment is unavailable; this preserves recovery without inventing missing
qualification evidence. Session directories remain local, single-writer
workspaces. Repository demonstrations require a Git checkout.

## Release validation

The final local suite passed **1,387 tests**, with 22 optional skips on Python
3.12. The existing offline teaching-quality and recorded-Jev regression passed
for all three bounded demonstration skills. This preserves their historical
scope and does not supply fresh full-scope qualification. The browser workspace
was also exercised with approved prediction, explicit review, and revision history.

Focused lifecycle tests cover old sessions, qualified adoption, sufficient and
insufficient evidence, retained errors, frozen cohorts, altered evidence,
approved rollback, damaged archives, legacy recovery, optional qualification
integrity, and optional dependencies. Five bounded research checks verify
annotation isolation and uncached evaluation.

The release gate includes the full suite, existing teaching-quality regression,
documentation and version checks, lockfile consistency, wheel/source contents,
strict metadata checks, and a clean installation outside the checkout. CI tests
Linux Python 3.11–3.14 and macOS Python 3.13. The tag must match the package
version and the exact commit that passed CI. Publication is followed by separate
download, hash verification, installation, and lifecycle checks.
