# System 1 1.0: teaching a skill that can take over locally

The stable core supports explicit teaching or observed teacher responses,
held-out calibration and promotion, typed local decisions, saved skills,
corrections, and deterministic policy enforcement with signed audit evidence.
The architecture remains fixed local features plus small NumPy decision heads.
No LLM fine-tuning, provider framework, or new runtime dependency was added.

## Measured usefulness

| Skill | Accepted / evaluated | Correct / accepted | Correct / evaluated |
|---|---:|---:|---:|
| Support triage | 92/104 | 91/92 | 98/104 |
| Model routing | 94/96 | 94/94 | 95/96 |
| Operation triage | 125/132 | 125/125 | 131/132 |

Manual teaching and teaching from recorded Jev responses reach these same counts.
Teaching and calibration take about 0.2 seconds after examples exist; saved skills
are 25–32 KiB and uncached local decisions take about 0.5 ms on Apple M4 Pro.
These times exclude creating/reviewing examples and application tool execution.

Reproduce with `python benchmarks/quality/evaluate_release.py` (offline, no key).
The [report](../../benchmarks/quality/results/stable_release.json) includes every
prediction, review outcome, latency, token usage, teacher model, confidence
interval, and cache digest. CI checks the observed 95% accepted correctness and
80% acceptance targets for each skill, not a guarantee about future traffic.

The [datasets and methodology](../../examples/teaching/README.md) disclose authored
examples, retained earlier evaluation cases, and operation-triage development
iterations. Its fresh final confirmation cohort accepted 35/36, all correct.
Support has one accepted error. Neither high local agreement on these cases nor
conformal calibration establishes general Jev parity or malicious-input detection.

## Actual teacher evidence

The [recorded response cache](../../benchmarks/quality/results/jev_observations.json)
contains 1,313 successful live HTTPS responses from `jev-1.13.0` on the three
public authored datasets; collection completed with zero failed requests.
All evaluation labels agree with Jev. Three operation-teaching labels differ and
remain unchanged. The local compiler learns from the actual teacher labels.
Evaluation and reload run with sockets and teacher calls blocked.

Separately, the [live automatic handoff](../../benchmarks/quality/results/jev_live_cutover.json)
used default gates, no simulated fallback, and 357 successful teacher observations.
The final candidate used 215 fitting, 71 calibration and 71 validation cases.
All 71 complete validation decisions matched and were accepted; the attempt-ten
exact lower bounds were 88.86%, exceeding the configured 80% defaults. After
promotion, all 40 fresh structured tickets were accepted and correct, with zero
further teacher calls and identical answers/uncertainty after reload. Observation
took 116 seconds; the skill was 5,075 bytes. The small repeated topic vocabulary
proves the workflow, not diverse semantic generalization. New ticket IDs are not
proof of independent real-world scenarios.

Three additional [live typed contract checks](../../benchmarks/quality/results/jev_typed_contract.json)
passed mixed Choice, Noul and ordinal Score calls. This is the documented basic
SDK decision contract; full SDK transport and Pydantic parity are not claimed.
No price was returned by these calls, so no monetary savings are inferred.

## Reliability changes

- Examples-only teaching uses LAC scores; legacy skills retain APS. Temperature
  fitting and uncertainty calibration use distinct observations, with duplicate
  prompts counted once. Strict MultiChoice decisions require a unique complete
  assignment, including a valid empty assignment.
- Recalibration persists in saved skills. Corrections invalidate the changed
  heads' evidence. Model operations are synchronized, distinct nearby inputs
  cannot share compiled logits, and cache receipts bind the current request.
- Promotion counts complete decisions within related-evidence groups. Exact
  lower bounds test agreement and acceptance. Fresh validation blocks and a
  summable attempt budget prevent repeatedly testing the same evidence. The
  statistical interpretation still requires independent, representative groups.
- Malformed teacher answers never enter teaching history. Missing classes and
  insufficient evidence defer takeover. Drift evidence stays per schema.
- The guard no longer repeats its ten seed calibration examples to suggest more
  evidence. Explicit policy grants remain the supported permission mechanism.
  Statistical classifications are routing suggestions, not permission grants.

Existing tests cover synchronous/asynchronous SDK use, all local field types,
correction and persistence, promotion, teacher failures, ledger/receipt integrity,
permission denial, and LangChain/MCP/ASGI/gRPC boundaries. Optional MLX/neural and
gaming/emulation examples remain experimental. Earlier example reviews and seed
benchmarks are historical; their identified reload and counter-only takeover
problems have been fixed and their unsupported performance claims removed.

## Upgrade from 0.2.2

Install `system1==1.0.0`. Python 3.11–3.14 are supported by CI. Public teaching and
basic adapter calls remain the same. Default promotion may take more observations;
insufficient evidence keeps the teacher answering instead of forcing cutover.

Newly saved `.s1m` files use format v2, recording score semantics explicitly.
Version 1.0 reads v1 skills with their original APS behavior. A skill generated by
the published 0.2.2 package was loaded with identical values, probabilities,
prediction sets and review behavior. The published older reader rejects v2.
Upgrade all readers before distributing new skills; retain original files for
rollback. Invalid metadata and weights now fail explicitly.

After `learn_from_tier2(...)`, recalibrate changed heads on separate examples
before relying on strict local acceptance. Saving does not restore stale evidence.
Recompiling from retained examples remains the simplest reproducible update path.
Default guard seed examples now request review unless an explicit policy resolves
the action. Use `enforcement_profile=True` for application tool permissions.

Follow the [deployment boundaries](../deployment.md) and
[adapter contract](../typesafe.md). A stable library does not remove the need to
validate each skill on representative traffic and enforce review decisions.
