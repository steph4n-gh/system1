# System 1 1.0.2

System 1 is not an LLM. It teaches a bounded decision head from examples or
observed answers, validates it, then runs and saves that skill locally. This patch
makes qualification more explicit and updates the package's documentation and
evidence without adding a runtime dependency. Optional MLX provides Apple Silicon
acceleration for decision-head operations; a GPU is not required. The reported
quality-round timings use the NumPy path.

## What changed

- Add a [beginner teaching walkthrough](../guides/first_skill.md), an editable eight-example lesson file, and simple options to teach from your own file, try a message and save a separate candidate. Explain labels, corrections and review requests in plain language.

- `PromotionPolicy(min_accepted_agreement=.95)` requires both 95% observed agreement and a sufficient exact lower bound among accepted validation groups. The confidence budget covers all three exact bounds and repeated attempts. The default `None` retains the original policy.
- Sync and async observation clients expose the compiler's existing `regularization` setting, with the same default of 1.0. A promotion manifest records the selected qualification thresholds; the report and audit metrics include the accepted-agreement lower bound.
- A fixed observation recipe using more examples and regularization 0.1 improves SMS takeover on the old official test: **954/980 correct accepted decisions (97.3%)**, versus **897/963 (93.1%)** previously. It takes 2,961 original-label observations and makes no live API calls. Saved/reloaded outputs match with networking blocked.
- The README, guides, architecture, papers, examples and deployment instructions distinguish current behavior from historical results. The source distribution includes the deployment templates. Unsupported promotional graphics were retired and CI checks local documentation links and version labels.

No migration is required for existing clients or saved skills. The stronger
quality policy is opt-in. It measures agreement with the teacher; validate
against independent labels to measure correctness.

## What remains unresolved

Under the stronger policy, banking and assistant observation remain deferred:
the available evidence does not establish a 95% accepted-agreement lower bound.
On 40 fresh authored SMS probes, the promoted skill achieves only **27/33 correct
accepted answers (81.8%)**. Unchanged explicitly taught banking and SMS skills
also miss the correctness target on the new probes.

A proposed 36-lesson routing change improves an older difficult cohort but misses
fresh coverage and introduces an accepted error on the original cohort. It is
retained for diagnosis and **not adopted** into the primary example. Existing
primary lesson files and the published historical results remain unchanged.

See the [complete quality round](../../benchmarks/quality/quality_round/README.md)
for all counts, intervals, errors, provenance and reproduction commands. Old
public tests are regression evidence after their prior inspection. The new
probes share authorship with the proposed lessons and are diagnostic evidence,
not an independent customer benchmark. This patch does not establish universal
teacher parity or general language understanding.

## Validation and release

The runtime tests exercise accepted-subset errors, too little independent
evidence, repeated-attempt spending, missing acceptances and invalid thresholds.
The local full suite passes **1,098 tests**, with 14 optional tests skipped.
Existing lifecycle, concurrency, SDK adapter, game, integration and saved-skill
checks remain in that suite. The quality round blocks sockets and teacher
calls during local evaluation. Packaging checks build and inspect wheel/sdist
artifacts and run installed-wheel smoke checks outside the checkout.

The release tag is pushed only after CI passes on the exact version commit.
That tag triggers the existing PyPI Trusted Publishing workflow.
